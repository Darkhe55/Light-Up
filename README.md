# 点灯 Light Up（Akari）

一个基于 Web 的点灯（Light Up / Akari）谜题游戏，原生 SVG 渲染，内置逻辑解题器。

## 在线体验

克隆后运行：

```bash
npm install
npm start
```

`npm start` 会等 dev server 真正就绪后再用默认浏览器打开，地址是
**http://127.0.0.1:5178/**。

> 也可以用 `npm run dev`，但不会自动打开浏览器。

### 为什么必须用 5178，而不是 Vite 默认的 5173

浏览器 HTTP 缓存按 `origin(host:port) + path` 存储。5173 是 Vite 的默认端口，
机器上任何其它 Vite 工具（`npx vite`、`vite preview`、其它项目的 dev server）
只要没显式指定端口就会落到 5173，并把它们自己的 `/src/main.ts` 等条目写进同一个
origin 的缓存。之后普通刷新会直接复用这些条目 → 点灯拿到的是别人的/旧版本的模块 →
页面卡在加载，只有 Ctrl+Shift+R 绕过缓存才好。

兄弟项目正是各占一个端口所以从来不受影响：划斜线 5174 / 帐篷 5175 / 黑白 5176 /
数回 5177，点灯用 5178。端口被占用时 `strictPort` 会直接报错，不会悄悄换端口。

配套还有两层保险：

- dev server 所有响应都带 `no-store`，自己永远不会产生可复用的陈旧条目；
- 文档响应带 `Clear-Site-Data: "cache"`，每次导航都清掉该 origin 的 HTTP 缓存；
- `index.html` 里的兜底脚本：模块没加载成功或 20 秒没进入游戏时，自动做一次
  绕过缓存的刷新（每个标签页最多一次，不会死循环），并摘掉可能被别的工具注册的
  Service Worker；仍然失败才在页面里给出一条提示，同时把原因 post 到开发服务器
  打在终端里。正常加载时它什么都不做，也没有加载界面。

### 打不开怎么办

- **终端报 `Port 5178 is already in use`**：先结束占用进程
  （`netstat -ano | findstr :5178` 找到 PID 后 `taskkill /F /PID <PID>`），
  或临时换端口 `npx vite --port 5180`。
- **终端出现 `[boot] 页面启动失败：…`**：这行就是原因，照着排查即可。
- **改了代码没生效**：正常刷新就行，所有响应都不缓存。

## 游戏规则

题板由空地和墙壁组成，部分墙上有数字：

- 在空地放**灯泡**，灯泡照亮横向和纵向，直到被墙挡住
- 数字墙**四邻**（上下左右）的灯泡数必须等于数字
- **所有空地**都要被照亮
- 任意两个灯泡**不能互相照亮**（同行/同列隔墙之内只能有一个灯泡）

## 操作

- **左键**：空 → 灯泡 → × → 空（按住拖拽可连续涂同一动作）
- **右键**：直接标 × / 取消
- **中键拖拽**：平移画布；**滚轮**：缩放；`+` / `−` / `0`：放大 / 缩小 / 复位
- `Z` / `Shift+Z`：撤销 / 重做；`C`：检查；`H`：提示一格
- `L`：逻辑解题 / 停止回放；`P`：暂停 / 继续回放
- `R`：随机抽题；`M`：音效开关；`Esc`：清空

## 功能

- **题库**：内置 9 题，从 5×5 入门到 12×12 挑战，全部经**唯一解**校验
- **自定义题板**：侧边栏输入任意尺寸（3–25）和墙/数字，点击循环
  空 → 墙 → 0 → 1 → 2 → 3 → 4 → 空，也可键盘录入；载入即入库，
  支持**唯一解校验**和**求解**
- **逻辑解题**：点「逻辑解题」从当前盘面自动推理（4 条人类规则），动画回放每一步；
  回放中该按钮变成「停止回放」，再点一次立即停止并恢复其它按钮，回放期间其它按钮与
  盘面交互全部屏蔽。按 `P` 可暂停/继续回放。规则只对「未定且未被照亮」的候选位下结论：
  亮格与打叉格同等视为不能放灯泡，**不把亮格打叉**，省掉这些操作
- **实时校验**：数字墙超了标红、灯泡互照红环、未照亮格素底、满足的数字变灰
- **提示一格**：枚举多个解，找「所有解一致且与当前不同」的格子揭示
- **显示解**：填入参考解（自定义盘走回溯求解）
- **进度保存**：自动保存每道题的进度，刷新不丢失
- **撤销/重做**：完整操作历史（一次手势算一步）

## 技术栈

- Vite + TypeScript
- 原生 SVG（无框架）
- 题库与进度存放在**项目内 `data/` 目录**（见下）

## 数据存放在哪

| 内容 | 位置 |
|---|---|
| 自定义题库 | `data/library.json` |
| 每题进度（灯泡/× 标记） | `data/progress.json` |
| 上次玩的题 | `data/last-puzzle.json` |

运行 `npm start` / `npm run dev` 时，这些文件由开发服务器读写，**和浏览器缓存目录无关**，
换浏览器、清浏览器数据都不会丢。首次启动会把浏览器 localStorage 里的旧题库/进度自动迁进来
（只补项目里没有的，不覆盖）。

没有开发服务器时（例如 `npm run build` 后的静态页面）自动降级用 localStorage，功能不变。

## 项目结构

```
src/
  main.ts         主逻辑：UI、交互、逻辑解题回放
  render.ts       SVG 棋盘渲染
  logic.ts        逻辑解题规则引擎
  solver.ts       约束传播 + 回溯求解器（唯一解校验）
  puzzles.ts      题库加载
  puzzles-data.ts 静态题库数据（自动生成）
  state.ts        棋盘状态与段结构
  validate.ts     解的合法性校验
  store.ts        项目内 data/ 存储（localStorage 降级）
  library.ts      自定义题库
  audio.ts        Web Audio 合成音效
  styles.css      样式
```

## 命令

```bash
npm run dev       # 开发服务（127.0.0.1:5178）
npm start         # 开发服务 + 就绪后自动打开浏览器
npm run build     # tsc --noEmit + vite build
npm run gen       # 重新生成题库
npm run check     # 审计题库（参考解合法 + 唯一解）
npm run logic-test # 逻辑引擎自检（不打叉亮格/不摆错灯泡/终态合参考解）
```

冒烟测试（playwright）：先 `npx vite preview --port 5179`，再 `node scripts/ui-check.mjs`。
